## 1. 結論 (TL;DR)

**self-critique を「切るべき」という結論は出せない。デフォルト (ON) を維持する。**

sc-off が見かけ上 +4.69 点優位だが、これは

1. 事前登録済みのノイズ下限 (±4.8、独立 2 群の差なら ±6.8) を**下回る**
2. paired t 検定で **p ≈ 0.48** (有意差なし)
3. **中央値・テーマ多数決は逆に sc-on 優位** (median diff −3、16 テーマ中 9 で ON が上)
4. sc-on run の**後半に環境劣化の交絡**があり、平均差の符号自体が信頼できない

の 4 点から、品質差として採用できない。一方で sc-off に切り替える積極的根拠 (コスト削減) も
+0.62 call/テーマ程度で、初回合格率の低下 (6/16 → 1/16) と引き換えになる可能性がある。
**判定保留のままデフォルト維持が、データに忠実な唯一の結論。** 白黒つけたければ §6 の再測定設計が必要。

## 4. 交絡: sc-on run の後半は環境劣化下で走っている

### 4.1 前半/後半分割 (実行順)

| 区間 | sc-ON | sc-OFF | 差 (OFF−ON) |
|---|---|---|---|
| 前半 8 テーマ | **88.1** | 83.3 | **−4.9 (ON 優位)** |
| 後半 8 テーマ | **62.0** | 76.3 | **+14.3 (OFF 優位)** |
| run 内の前後落差 | **−26.1** | −7.0 | |

**効果の符号が前半と後半で反転している。** 真の処置効果なら符号は安定するはず。
ON run だけ後半が 26 点クレーター化しており、外れ値 3 テーマのうち 2 つ (#15, #16) は
run 末尾、1 つ (#9) は後半開始直後に位置する。

### 4.2 wall-clock の決定的な非対称 (本分析での新規確認)

セッションの created_at → updated_at (結果ファイル mtime とも整合):

| run | 所要時間 | 1 テーマあたり |
|---|---|---|
| sc-ON | **21.5 時間** (06-04 22:50 → 06-05 20:22 JST) | ~81 分 |
| sc-OFF | **2.3 時間** (06-06 06:57 → 09:16 JST) | ~9 分 |

同じ 16 テーマで **9 倍の所要時間差**。FINDINGS §5 が記録する LM Studio の
sustained-load 劣化 (15s/call → 3.5min/call で oscillate) と整合し、
**2 つの run は比較可能な環境条件で実行されていない**ことの物証。
blocked A/B (ON を全部回してから OFF を回す) はこの環境では処置と環境状態が完全に交絡する。

### 4.3 ノイズ下限との照合

eval-repeat.sh の実測 (同一お題 ×6) で per-theme stdev ≈ 9.6。そこから:

| 基準 | 値 | 観測差 +4.69 は |
|---|---|---|
| 16 テーマ平均の 2SE (FINDINGS §5.5 の事前基準) | ±4.8 | **下回る** |
| 独立 2 群の平均差の 2SE (より厳密) | ±6.8 | **下回る** |
| paired t 検定 (本分析、外れ値込み) | p ≈ 0.48 | **有意でない** |

どの基準でも sampling noise と区別できない。

## 5. 切る場合に失うかもしれないもの (コストと初回合格率)

self-critique の実装 (`tanka.py` L216-227, `config.SELF_CRITIQUE_ENABLED`) は
**compose 直後・初回 validate 前に 1 回だけ** 走る +1 LLM call/生成。refine ごとではない。

- **初回合格率: ON 6/16 vs OFF 1/16**。paired で見ると不一致ペアは **ON だけ初回合格 5 / OFF だけ 0**
  (McNemar 正確検定 両側 p = 0.0625)。有意水準 5% には届かないが、今回唯一
  **方向が一貫し、かつ機構的に自然な信号** (validator に出す前に自己修正するのだから
  初回合格が増えるのは因果として素直)。しかも OFF run は「良い環境」(2.3h で完走) でも 15/16 が初回不合格。
- **コスト**: 総 LLM call/テーマ ≈ plan+compose+SC+refine で ON 5.56 vs OFF 4.94。
  SC の +1 call は refine 削減 (attempt 3.56 vs 3.94) で約 4 割相殺され、正味 **+0.62 call/テーマ (~13%)**。
  「+1 call 丸ごと無駄」ではない (ただしこの差自体も n=16 の点推定でノイズ範囲)。

つまり「切れば安くなる」のリターンは小さく、初回合格率 (= 体感レイテンシ) を悪化させる
リスクと引き換えになる可能性がある。

## 6. 最終結論と推奨アクション

### 結論

**self-critique フェーズは切らない (デフォルト ON を維持)。**

理由:
1. OFF 優位の根拠 (+4.69) はノイズ下限以下・p≈0.48 で、統計的に存在を主張できない
2. その +4.69 は環境劣化下の後半 3 外れ値が作った数字で、中央値 (−3)・多数決 (9/16)・
   交絡の少ない前半 (ON +4.9) はむしろ ON 優位 — **効果の符号すら確定しない**
3. デフォルト変更には「改善の証拠」が必要だが、この実験はそれを提供しない
   (「OFF にしても悪化しない」の証明にもなっていない)
4. 切ると初回合格率の信号 (McNemar p=0.0625、機構的に自然) を捨てるリスクがあり、
   正味コスト削減は ~0.6 call/テーマと小さい

これは FINDINGS.md §5.5 の「存続判断は保留」と同じ向きの結論だが、本分析は per-theme paired
データから独立に検証し、さらに (a) 中央値/外れ値分解、(b) McNemar、(c) wall-clock 9 倍差という
物証を追加した。

### 白黒つけたい場合の再測定設計 (必須要件)

1. **paired/interleaved**: テーマごとに ON→OFF を交互実行し、両条件が同じ LM Studio 状態を経験する
2. **fresh reload + run 間インターバル** (FINDINGS §5 の運用)、eval 中の診断 probe 禁止
3. 検出力: per-theme paired sd ≈ 26 (今回実測、外れ値込み) に対し 5 点差を 2SE で検出するには
   ペア数 ≈ (2·26/5)² ≈ 100 ペア相当。**16 テーマ × 各 3 run の平均**等で per-theme 分散を潰すのが現実的
4. 主要評価指標を事前登録する: avg_final_score だけでなく **初回合格率と総 LLM call 数** (コスト対効果が本来の問い)
