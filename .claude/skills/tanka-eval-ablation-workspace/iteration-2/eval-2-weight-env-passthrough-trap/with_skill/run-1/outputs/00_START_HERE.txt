================================================================================
重要な注意点 (必読)
================================================================================

⚠️  PASSTHROUGH 罠 (SKILL.md §2 で指摘)

❌ 効かない:
   export TANKA_W_REPEATED_WORD=12
   docker compose up -d backend

✅ 正しい:
   cd app
   TANKA_W_REPEATED_WORD=12 docker compose up -d backend

理由: docker-compose.yml に明示的に列挙されていない env は、ホストで
export しても backend コンテナに届かない。

⚠️  FAILURES リセット (SKILL.md §1.6 で必須)

各 variant (baseline, treatment) の直前に:
   curl -X DELETE http://localhost:8001/api/failures

理由: 重み変更は long-term failure memory の lesson 選定に交絡する。

⚠️  判定基準の事前登録

スコア差がこの幅を超えて初めて「改善/劣化」と結論する:

   50 お題の場合: ±2.7 (2SE)

この幅内の差は統計的に区別できないノイズです。

================================================================================
判定基準 (事前登録)
================================================================================

**問い**: repeated_word の重みを 3→12 に上げた場合、
         最終スコアと違反出現率への影響は?

**お題**: 50 (eval_themes.json) — 確定判断用フルセット

**ノイズ下限 (2SE)**: ±2.7 (n=50)

**判定**:
  スコア差 > +2.7        → ✅ 改善 (採用の検討)
  ±2.7 以内              → ⚪ 判定不能 (ノイズ内)
  スコア差 < -2.7        → ❌ 劣化 (不採用)

**追加指標**:
  repeated_word 残存率が 20% 以上低下 → 「ルールが機能」

================================================================================
交絡対策 (3 つ)
================================================================================

1. Failures リセット
   各 variant 直前に: curl -X DELETE http://localhost:8001/api/failures
   理由: 重み変更は lesson 優先度に交絡

2. LM Studio Fresh Reload
   eval 前に: lms stop && lms server start
   理由: 連続負荷で劣化 (15s/call → 3.5min/call)

3. docker-compose.yml 環境変数追加
   TANKA_W_REPEATED_WORD: ${TANKA_W_REPEATED_WORD:-3}
   理由: passthrough 罠 (export だけでは backend に届かない)
