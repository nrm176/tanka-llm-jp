================================================================================
実験設計サマリー: TANKA_W_REPEATED_WORD 重み比較 (3 vs 12)
================================================================================

【問い】
repeated_word ルールの重みを 3 (既定) から 12 に 4 倍に上げた場合、
・repeated_word 違反の出現率がどのくらい抑制されるか
・全体スコアにどのような影響を及ぼすか

【実験設計】
┌──────────────────────────────────────────┐
│ 変数           │ 値                      │
├──────────────────────────────────────────┤
│ 変更の種類     │ 環境変数 (env 切替)     │
│ 環境変数       │ TANKA_W_REPEATED_WORD   │
│ 既定値         │ 3                       │
│ 新値           │ 12                      │
│ お題セット     │ 50 (eval_themes.json)   │
│ 所要時間/arm   │ 25～60 分               │
│ 判定基準       │ ±2.7 (n=50, 2SE)        │
│ 主要指標       │ (a) repeated_word 残存率│
│                │ (b) 共通重み再採点スコア│
└──────────────────────────────────────────┘

【交絡対策 (必須)】
1. failures リセット
   - 重み変更は lesson 選定に交絡するため各 run 直前に実施
   - curl -X DELETE http://localhost:8001/api/failures

2. LM Studio fresh reload
   - 各 variant 前に fresh reload (20 分以上アイドルなら不要)
   - lms stop && lms server start

3. docker-compose.yml への環境変数追加
   - TANKA_W_REPEATED_WORD: ${TANKA_W_REPEATED_WORD:-3}
   - passthrough 罠 (SKILL.md §2 参照) を回避
   - export では backend に届かない

【適用方法】
1. docker-compose.yml を編集 (diff は別ファイル)
2. baseline: TANKA_W_REPEATED_WORD=3 で ./eval.sh w-repeated-3
3. treatment: TANKA_W_REPEATED_WORD=12 で ./eval.sh w-repeated-12

各 run の前に failures をリセット:
  curl -X DELETE http://localhost:8001/api/failures

【判定基準】
スコア差が ±2.7 を超える  → 改善/劣化
スコア差が ±2.7 以内      → 判定不能 (ノイズ内)

追加指標:
- repeated_word の残存率が 20% 以上低下 → 「ルールが機能している」

【記録】
1. app/backend/eval/FINDINGS.md に結果を追記
2. PR の本文に before/after の数値と判定根拠を記載
