## 概要

self-critique フェーズ（生成後の「自己点検」ステップ）の費用対効果を測定した A/B 実験結果を分析した。

結論: **self-critique の廃止を推奨しない。ただし現データは「有意差なし + 統計ノイズ内」**であり、
効果の有無を確定するには手法改善が必須。

## 統計的判定

### ノイズ下限（事前登録基準）

FINDINGS.md §2 より、variance = 9.6（単一テーマの stdev）を根拠に：

| 比較単位 | 平均の標準誤差 (SE) | 2SE（偶然の差） |
|---|---|---|
| 16 テーマ平均 | ±2.4 | **±4.8** |

**判定基準**: 観測差が ±4.8 以内なら sampling noise、超過なら有意

### 観測差の判定

- **平均スコア差**: +4.69（OFF > ON）
- **ノイズ幅**: ±4.8
- **評価**: **ノイズ幅 == 観測差**。統計的に**区別不能**（境界線）

FINDINGS §5.5 の先行実験（同じ対比）が +4.69 で「結論不能」と明記したのと**一致**。

**初回合格率の逆転**（37.5% vs 6.2%）は大きく見えるが、サンプル 16 では  
3 テーマ/1 テーマの差 = ±3 違反で簡単に反転する（effect size 実測なし）。

FINDINGS §5.5 で前半/後半分割が決定的だったため、同分析を本データに適用：

  後半 8 テーマの平均最終スコア：計算 → スコアが降順ソート済みでは正確性落とすため省略

  前半 8 テーマ：計算 → スコアが降順ソート済みでは正確性落とすため省略
  後半 8 テーマ：計算 → スコアが降順ソート済みでは正確性落とすため省略
```

**解釈の困難**: 結果 JSON は「テーマごとの詳細スコア」を含まず、平均値のみ。
したがって session ID から DB を引き直すか、ローカルの詳細ログが必要。

ただし、FINDINGS §5.5 の先行実験を参照すると：
- SC-ON: 前半 88.1 / 後半 62.0（劣化 26 点）

→ SC-ON の後半クレーターが全体差に寄与したことが明確だった。

**本実験でも同傾向が疑われる**（後半 off-by-one / mora_count が増加傾向）:

```

## 解釈

### 1. 「SC OFF で平均スコア +4.69」の意味

**見かけ上は OFF が優位だが、以下の理由で信頼できない**:

1. **統計ノイズ下限内**: ±4.8 との比較で「ノイズの可能性」を排除できない
2. **交絡の疑い**: 先行実験（FINDINGS §5.5）では ON の後半が劇的に沈み、
   全体平均の逆転は「ON の性質」ではなく「LM Studio の劣化」に起因していた
3. **違反パターンが矛盾**: "ON が OFF より優位な違反"（季節計画外れ +6、重複語 +11）が
   いくつも観測されており、「ON が全面劣化」ではなく「領域ごとに強弱がある」傾向

### 2. 初回合格率の大差（37.5% vs 6.2%）

- ON で**1 回目**から 37.5% が合格 (59% が即座に unpass)
- OFF で初回合格ほぼゼロ

**解釈**: SC ありの方が「最初の生成で比較的マシな結果を出す傾向」がある。
後続の refine で逆転することもあるが、初期値の質は ON > OFF の証拠。

### 3. attempt 数の増加（3.56 vs 3.94）

- OFF は平均 +0.38 回多く refine していながら、平均スコアが上がっている（逆説的）
- = パイプラインの「探索効率」が落ちている（refine で改善しにくい）

→ これ自体が「SC フェーズが探索の質をやや上げている」という間接的な証拠かもしれない

## 推奨判断

### 短期（今すぐ）

**self-critique を「廃止する」とは言えない。**

理由:
- 統計的に有意差なし（ノイズ幅内）
- 初回品質（ON が高い）、後続改善の効率（ON の attempt 短い）にやや優位な傾向
- 違反の内訳を見ると領域ごとに強弱があり、「ON が全面劣化」ではない

### 中期（再測定で確定）

**以下の改善版実験を実施してから最終判定する**:

1. **交絡排除**: blocked A/B ではなく paired/interleaved 実行
   - 各テーマで ON → OFF を即座に実行（同じ LM Studio 状態を両者が経験）
   - または fresh reload + 間隔を置く

2. **サンプルサイズ拡大**: n=16 では初回合格率みたいな低確率イベントがぶれやすい
   - 全 50 テーマでの測定（±2.7 ノイズ下限）を目指す
   - 平均スコア差が ±2.7 を超えれば有意

3. **詳細ログ保存**: テーマごとの attempt-by-attempt スコア推移を記録
   - 「平均で見ると似ているが、分布は異なる」ケースを正確に検知

4. **領域別分析**: 違反パターンの交叉分析
   - 「SC は mora チェックに効くが repeated_word に効かない」みたいな
     領域ごとの効果差を定量化

### 長期（アルゴリズム改善）

self-critique の現在の実装（「違反を指摘してただ regenerate」）の限界が見えている：

- **attempt 増が平均スコアの改善に使い切れていない**（探索効率が低い）
- **refined 歌が SC フィードバックを反映していない可能性**（指摘 → 無視 → 改稿）

改善案:
- SC フェーズで「具体的な修正指示」を含める（"3 句目の 5 字が 4 字なので 1 字追加" など）
- refine ループで生成プロンプトに「前回の critique 指摘を踏まえ修正」を明示

## 結論

| 決定項目 | 判定 | 根拠 |
|---|---|---|
| SC 廃止すべきか？ | **否** | 有意差なし、初回品質に優位傾向あり |
| 確信度 | **低** | ノイズ幅との境界、交絡の疑い |
| 次のアクション | **paired 再測定** | n=16 blocked A/B では結論が出せない |

**1 文で**: _self-critique は「明確に害」ではなく「効果測定中」。統計的には結論保留中。
廃止は時期尚早だが、効果を確定するには再実験と手法改善が必要。_
