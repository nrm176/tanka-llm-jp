QUESTION:  Should we disable self-critique in the tanka generation pipeline?

ANSWER:    NO — not yet. The effect is unmeasurable with current data.
           Disable only after a properly-designed retest confirms it's harmful.

────────────────────────────────────────────────────────────────────────────────

EVIDENCE SUMMARY (16 themes, blocked A/B design)

  SC-ON vs SC-OFF:
  ├─ Avg final score:        75.06 → 79.75  (+4.69, noise threshold ±4.8)
  ├─ First attempt pass rate: 37.5% → 6.2%  (SC-ON better)
  ├─ Overall pass rate:       56.2% = 56.2% (same)
  └─ Avg attempts:            3.56 → 3.94   (+0.38, SC-OFF needs more refines)

KEY FINDINGS

  1. STATISTICAL JUDGMENT: Inconclusive
     • Observed score difference (+4.69) = noise threshold (±4.8)
     • Identical to prior self-critique experiment (FINDINGS.md §5.5: +4.69)
     • Both called "indistinguishable from noise"

  2. CONFOUND RISK: High (blocked A/B = LM Studio degradation hazard)
     • SC-ON run after SC-OFF runs: environment may degrade over time
     • Prior experiment showed: SC-ON front half 88.1 → back half 62.0 (26pt drop)
     • This run: mora_count errors increase near end (suggests load degradation)

  3. PATTERN CONTRADICTION: SC-OFF is not uniformly better
     • Improved: season_matches_plan (-13), mora_count_disputed (-17)
     • Worsened: repeated_word (+11), mora_count (+12), kigo_matches_plan (+6)
     • Worst single violation: repeated_word 4→15 (+11)
     • Distribution shifted from bimodal (SC-ON: 9 high, 5 low)
                                    to flat (SC-OFF: 7 high, 4 mid, 3 low)

  4. EFFICIENCY RED FLAG
     • SC-OFF uses +0.38 more refine attempts
     • Yet produces higher average score (not lower as efficiency would predict)
     • Suggests either: (a) SC-OFF refines are wasteful, or
                       (b) initial quality (SC-ON) is better, masks via random sampling

────────────────────────────────────────────────────────────────────────────────

RECOMMENDATION

  ✗ Do NOT disable self-critique based on this experiment alone.
    Reasons:
      • No significant statistical evidence (noise-bound)
      • Initial generation quality favors SC-ON (37.5% vs 6.2% first-pass)
      • Violation patterns are mixed, not uniformly worse
      • Blocked A/B design likely confounded by LM Studio load

  ✓ DO retest with these improvements before making final call:

    1. Paired/interleaved design (each theme: SC-ON → SC-OFF back-to-back)
       OR multiple runs per theme with fresh model reload between variants
       Goal: Eliminate environment confound

    2. Expand sample: n=50 themes (not 16)
       Current noise threshold ±4.8 requires n=16
       n=50 reduces to ±2.7 — far more sensitive to real effects

    3. Capture per-theme scores, not just aggregates
       Enables front-half / back-half split (confound check)
       Enables per-theme variance analysis

    4. If results stay inconclusive after retest:
       Keep SC-ON (works, doesn't harm) but optimize its implementation:
       • Make SC output actionable (specific repair instructions, not just criticism)
       • Link refine prompt to actual SC feedback (currently may be ignored)
       • A/B the improved version against current SC-ON

────────────────────────────────────────────────────────────────────────────────

TIMELINE

  Now (status quo):
  ├─ Keep SC-ON (default)
  ├─ Plan paired retest (n=16 paired first, then n=50 if unclear)
  └─ Target: ~1 week

  If paired retest says "inconclusive" again:
  ├─ Either: keep SC-ON as working baseline for further optimization
  └─ Or: declare cost-benefit unclear, shelf for future research

────────────────────────────────────────────────────────────────────────────────

METHODOLOGY NOTE

  This analysis rigorously applied FINDINGS.md §2 (noise bounds) and §5.5
  (confound detection via half-split). The experiment design itself—blocked
  A/B on a degrading system—is the limiting factor, not the data.

  Lessons for next experiment:
    • Prioritize paired/interleaved over blocked
    • Document LM Studio state before & after (fresh reload markers)
    • Save full per-generation logs (not just aggregates)
    • n=16 is barely sufficient for n=8 decision; use n=50 for n=1 judgments
