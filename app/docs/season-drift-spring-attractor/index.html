問題 ③ · 増幅要因

RAG が「春」アンカーを注入していた

季語「蛍」は古典コーパスに無く（exact 0件）、季節=夏 フォールバックで2首を注入。その1首が…

春過ぎて 夏来にけらし 白妙の 衣ほすてふ 天の香具山 — 持統天皇

「参考」として見せた歌の冒頭が「春過ぎて」。few-shot #1 と合わせ、春の磁石がモデルの目前に2つあった。 RAG は春ドリフトを抑えるどころか助長した可能性が高い。
問題 ④

refineが回復に失敗 ＋ 不合格を無警告で採用

回復の失敗

4試行すべてが春/花の basin に留まった。スコアは乱高下（試行2で17へ悪化）。 best-of-N が誤った attractor に捕捉された。

不合格作の確定

47点（<80）の歌を最終結果として提示。fail-soft で best を返す設計だが、 「規定未達」の警告ラベルが無い。通常の完成短歌と区別がつかない。

ユーザーには「お題違反・季節違反・字足らず」の歌が、欠陥の表示なく確定した。
問題 ⑤

validator の検出ギャップ ＋ 永続化バグ

時刻の見逃し

theme_time_mismatch は矛盾しか見ない。出力に時刻語が無く「夕暮れ」を全く詠めていない＝欠如は検出対象外。

お題直接照合なし

お題遵守は plan 整合経由でしか効かない。plan も春に流れていたら何も捕まえられない構造欠陥。

永続化バグ（コード）

max_refines_reached 分岐が best_score を保存しない（plateau 分岐は保存する）。事後分析を妨げた。

これらは「検出器側」の穴。真因（春の磁石）を断たない限り、検出を強化しても不合格作を量産するだけ。

なぜ「#1 だけ」が決定的か

季節の合う例を横着して写すなら #2〜#4 にも痕跡が出るはず。実際は #1 のみ。 これは「季節に合う例を選ぶ」ではなく例 #1 そのものへの固着を意味する。
